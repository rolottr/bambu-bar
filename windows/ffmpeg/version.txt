# The FFmpeg the camera decodes with (ledger D17): a minimal build of FFmpeg 9 (libavcodec 63, libavutil 61,
# libswscale 10) with only the h264, hevc and mjpeg decoders and swscale, LGPL version 2.1 or later (no external
# libraries, no --enable-version3/gpl/nonfree), shared libraries loaded at run time from the app's ffmpeg\ folder,
# built from FFmpeg's source tarball, unmodified. build.sh (beside this file) downloads exactly these files, checks
# their SHA-256, cross-compiles for win-x64 and win-arm64 with llvm-mingw, and writes the DLLs below with
# LICENSE.txt and SOURCE.txt. CI (.github/workflows/build.yml) runs it on Linux, cached by this file and build.sh.
# To update: change a version, its URLs and SHA-256 (and dlls on a new major version), run build.sh on a Mac, then
# run the decoder tests against its output (BAMBUBAR_FFMPEG=<out>/win-x64 on Windows).

# FFmpeg's configure flags for both arches (build.sh adds the target: --arch, --cross-prefix, --cc and so on).
# --disable-autodetect turns threads off too, hence --enable-w32threads (Windows' own: no libwinpthread DLL).
# --enable-small (-Os, fewer specialised code paths) halves the DLLs, and costs 10-15% decode time per frame
# (measured on Apple silicon with 1080p H.264 and HEVC: 2.4 ms instead of 2.1 ms, BGRA conversion included).
# --no-insert-timestamp (and build.sh's paths) make the DLLs the same from any folder on the same kind of host.
configure=--enable-small --disable-everything --disable-autodetect --enable-w32threads --enable-shared --disable-static --disable-debug --extra-ldflags=-Wl,--no-insert-timestamp --disable-programs --disable-doc --disable-network --disable-avformat --disable-avdevice --disable-avfilter --disable-swresample --enable-decoder=h264,hevc,mjpeg
# What the app ships in ffmpeg\ (FFmpeg.cs loads swresample-7.dll too if it's there, but needn't: no audio).
dlls=avcodec-63.dll avutil-61.dll swscale-10.dll
